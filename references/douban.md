# 豆瓣读书接入说明

用掌阅详情页拿到的 **ISBN** 作为钥匙，去豆瓣读书查评分，用来交叉验证「这本书到底好不好」。

所有数据来自公开页面，**不需要登录、不用 Cookie、不写任何豆瓣数据**。

## 1. 唯一可用的入口：ISBN 跳转页

```http
GET https://book.douban.com/isbn/<isbn>/
```

豆瓣会 **302 跳转**到对应的图书主页：

```http
GET https://book.douban.com/isbn/9787505745681/
  → 302 → https://book.douban.com/subject/30457109/
```

因此必须**跟随跳转**，并用最终 URL 里的 `subject/<id>` 作为豆瓣书号。

### ⚠️ 不要再用的接口

| 接口 | 实测结果 |
|------|---------|
| `https://api.douban.com/v2/book/isbn/<isbn>` | **HTTP 400**，v2 API 已下线 |
| `https://api.douban.com/v2/book/<id>` | 同上，废弃 |
| `https://www.douban.com/search?cat=1001&q=<isbn>` | 返回搜索页，需再解析，不如跳转页直接 |

v2 API 需要 API Key 且已停止服务，网上大量旧教程仍指向它，**实际不可用**。

## 2. 抓取字段

评分区块结构（`v:average` 的值**两侧带空格**，正则会踩坑）：

```html
<div id="interest_sectl">
  <div class="rating_wrap clearbox" rel="v:rating">
    <div class="rating_self clearfix" typeof="v:Rating">
      <strong class="ll rating_num" property="v:average"> 6.2 </strong>
      <span property="v:best" content="10.0"></span>
      <div class="rating_right ">
        <div class="rating_sum">
          <a href="comments" class="rating_people">
            <span property="v:votes">1863</span>人评价
          </a>
        </div>
      </div>
    </div>
  </div>
</div>
```

| 抓取项 | 正则 |
|--------|------|
| 评分 | `property="v:average">\s*([0-9.]+)\s*<` |
| 评价人数 | `property="v:votes">\s*(\d+)\s*<` |
| 书名 | `<title>(.*?)</title>`，去掉 ` (豆瓣)` 尾巴 |
| 无评分标志 | 页面含 `评价人数不足`（此时 `v:average` 标签在但内容为空） |

**注意**：`v:average` 标签**一定存在**，没评分时内容是空的（`>  <`）。所以不能只判断标签是否存在，必须匹配到数字才算有分。

### 只解析评分，不解析简介

评分和简介**都在 subject 页的同一份 HTML 里**，由同一次请求返回，不存在独立的「评分接口」或「简介接口」：

| 数据 | 来源位置（同一份 HTML） | 本工具是否使用 |
|------|------------------------|---------------|
| 评分 / 评价人数 | `<strong property="v:average">` / `<span property="v:votes">` | ✅ 取 |
| 书名 | `<title>` | ✅ 取（用于同名比对） |
| 内容简介 | `<div id="link-report">` 里的 `div.intro` | ❌ 不取 |

`douban_by_isbn()` 只有 **1 次** `douban_get()`。豆瓣简介虽在同一页，但**不解析、不返回**，输出里只有分数。少解析一段正文**不会减少请求数**（整页仍要拉回来），所以限流风险不变。

### 一条 ISBN 会触发 2 次 HTTP 请求

`book.douban.com/isbn/<isbn>/` 是 **302 跳转**，会立即跳到 `subject/<id>/`：

```http
GET /isbn/9787505745681/   → 302 →  /subject/30457109/
GET /subject/30457109/     → 200
```

`urllib` 默认跟随跳转，所以**查 1 本书，客户端会发出 2 次 HTTP 请求**。这是限流来得比预期快的原因之一（豆瓣侧如何计数未公开，此处只陈述我们发出的请求数）。

### 已实测不可用的替代通道

想找「更轻量、只取评分」的接口，实测**全部 403**（限流期间）：

| 通道 | 结果 |
|------|------|
| `book.douban.com/j/subject_rating_info?subject_id=` | 403 |
| `book.douban.com/j/subject_abstract?subject_id=` | 403 |
| `m.douban.com/rexxar/api/v2/book/<id>` | 403 |
| `m.douban.com/rexxar/api/v2/book/isbn/<isbn>` | 403 |
| `api.douban.com/v2/book/isbn/<isbn>` | 400（接口早已下线） |

注：这些 403 与主站同源——**是按 IP 封的**，所以无法判断它们在「未限流」时是否可用。从豆瓣现状看，v2 已废弃、rexxar 需鉴权，**ISBN 跳转页仍是唯一可靠的公开入口**。

## 3. 返回结构

`douban_by_isbn(isbn, local_title="")` 返回：

```json
{
  "ok": true,
  "rating": 6.2,
  "rating_count": 1863,
  "url": "https://book.douban.com/subject/30457109/",
  "title": "乌合之众：群体心理研究",
  "note": "",
  "title_match": true,
  "limited": false
}
```

| 字段 | 含义 |
|------|------|
| `ok` | 页面有效（`rating` 为 None 但 `ok=True` 表示「评价人数不足」） |
| `rating` / `rating_count` | 评分 / 评价人数，无评分时为 `null` |
| `url` | 豆瓣图书主页（跳转后的最终地址） |
| `title` | 豆瓣侧书名 |
| `note` | 失败原因或提示；正常时为空串 |
| `title_match` | `local_title` 与豆瓣书名是否吻合；`false` 说明配到了不同版本 |
| `limited` | 是否被限流（403/429 或反爬壳页）。为 `true` 时后续请求应停止 |

## 4. 反爬与限流（实测，重要）

### 4.1 请求要求

| 措施 | 说明 |
|------|------|
| User-Agent | **必须带**浏览器 UA，否则被拦。用桌面 Chrome UA，不要用掌阅的 App UA |
| `Accept-Language` | 带 `zh-CN` 更稳定 |
| gzip | 豆瓣返回 gzip，需手动 `gzip.decompress` |
| 请求间隔 | 脚本限 **并发 4 + 每次 0.5s** |
| 反爬识别 | 页面出现 `sec.douban.com` 或 `异常请求` 即判定被拦 |
| 404 | ISBN 豆瓣未收录，直接返回不重试 |

**注意额度换算**：因为存在 302 跳转，**查 1 本书 = 客户端发出 2 次 HTTP 请求**。所以 `--douban-top 20` 大约会发出 **40 次**请求，不是 20 次。

### 4.2 ⚠️ 限流是按 IP 的，且恢复极慢（本次踩坑实录）

在**一次集中测试约 60~80 次请求后**（含跳转，实际约 120~160 次），豆瓣开始对本机 IP 返回限流：

| 时间点 | 表现 |
|--------|------|
| 刚触发 | 部分请求 `429`，部分 `403`，个别 `200` 但只有 **3063 字节**（正常页 11~13 万字节）的反爬壳页 |
| 冷却 20 秒 | `403` |
| 冷却 150 秒 | `403` |
| 冷却 300 秒（5 分钟） | `403` |
| 冷却约 16 分钟（4 次 × 240 秒探测） | 全部 `403` |
| 冷却约 20 分钟后 | PC 站、移动站**都是 `403`** |
| 约 25 分钟（复测） | 仍然 `403` |

结论：

1. **不是「稍等一下就好」**——实测 20 分钟仍未恢复，量级可能是数小时；
2. **按 IP 封，换 UA / 换子域名（m.douban.com）都没用**；
3. 早期「无间隔连发 8 次未被封」的结论**不成立**——有累积阈值，短时小量才安全。

### 4.3 因此脚本必须做两件事

1. **识别限流并停止**：`douban_by_isbn()` 遇到 `403`/`429`，或 `200` 但页面小于
   `DOUBAN_MIN_PAGE`（20000 字节）时，置 `limited=True` 并给出明确提示；
   `douban_many()` 一发现 `limited` 就 `break`，**不再继续发请求**，避免把封禁拖长。
2. **默认限量**：`--douban-top` 默认 20。**这是保护性默认值，不要轻易调到几百**。

> 如果你需要批量查几十本以上，建议自己加本地缓存（ISBN → 评分），
> 或换用有官方配额的通道。硬刷的代价是整台机器一段时间内都查不了。

## 5. 三个必须知道的坑

### 坑 1：ISBN 不是唯一键，会张冠李戴

掌阅这边同一纸书拆成多个电子条目时共用一个 ISBN（详见 `api.md` 第 3 节）。传到豆瓣只会得到**整套书**的评分。

实测《平凡的世界》：

| book_id | 掌阅书名 | ISBN | 豆瓣返回 |
|---------|---------|------|---------|
| `11787714` | 平凡的世界（全3册） | 9787530216781 | 《平凡的世界》9.0（5225人） |
| `11817298` | 平凡的世界（第一部） | 9787530216781 | 同上（同一分） |
| —        | 平凡的世界（第二部） | 9787530216781 | 同上 |

所以脚本做了 **书名比对**（`_title_similar()`）：去掉括号副标题与「第X部/卷/册/集」后缀，再判断一方是否包含另一方。不吻合时 `title_match=False` 并附提醒。

### 坑 2：网文没有 ISBN，必然查不到

男频/女频书籍页没有 `bookinfo` 块，`isbn` 为空。脚本会**直接跳过**，不发请求。所以网文列表里不会出现豆瓣列，也不会有「豆瓣 —」，属于正常设计。

### 坑 3：覆盖率不是 100%

实测 15 个 ISBN（全部为掌阅出版类书籍）：

| 结果 | 数量 |
|------|------|
| 拿到评分 | 10 |
| 评价人数不足 | 5 |
| 豆瓣未收录（404） | 0 |

「评价人数不足」是正常结果，说明这本书太冷门，豆瓣还没攒够评分。

## 6. 降级策略

豆瓣是**外部第三方**，失败绝不能影响主流程（掌阅查询）：

- 网络超时/被拦/解析失败 → 只把 `douban` 字段置空或带 `note`，掌阅数据照常返回
- 列表命令里豆瓣查询在**掌阅数据抓完之后**才执行，串行追加
- 退出码不受豆瓣影响

`enrich_douban()` 负责编排：只挑有 ISBN 的前 N 本、附上本地书名做比对、汇总打印「几本拿到评分」、限流提示和逐条版本不匹配警告。
